# MM Prestige Motors website concept

A responsive boutique performance dealership website with a home page, searchable available/sold stock and individual vehicle pages. Built with React, Vite and React Router. The public pages use the showroom design from the Impulse Automotive concept, adapted for MM Prestige Motors in black and red. Fonts and images are local, so the preview does not depend on external image or font services; the only outside content is the Google map in the contact section.

## Run

Node.js 20.19+ or 22.12+ is required (validated with Node 24).

```sh
npm ci
npm run dev
```

To make and serve a production build:

```sh
npm run build
npm run preview
```

The build writes a page for every route with its own title, description, canonical URL and link-preview image: `stock.html`, `stock/<id>.html` for each car, `404.html`, and pages for the admin concepts. It also writes `robots.txt` and `sitemap.xml` (see `scripts/site-pages.mjs`). Absolute URLs use `SITE_URL`, or Vercel's production domain, or `https://mmprestiege.vercel.app`. `npm run preview` serves the build the way Vercel does. On other static hosting, serve `<path>.html` for clean URLs and `404.html` for unknown paths.

## Vercel deployment

Import this directory as a Vite project, or deploy with the Vercel CLI from the repository root. `vercel.json` builds the app with `npm run build` (which first reads the stock manager's cars, if a Blob store is connected), publishes only `dist`, deploys `api/stock.js` as a function and turns on clean URLs, so `/stock/<id>` is served from `stock/<id>.html` and unknown pages return a real 404 with the site's own not-found page. Hashed assets are cached for a year and photos for a day. Vercel project metadata is ignored by Git. Supply deployment credentials through the CLI or environment settings; never save them in repository files.

## Pages and interactions

- Header: Madi's number (a call button on narrow screens), a saved-cars link with a count once a car is saved, and every page link on desktop; phones use the menu, which also lists saved cars.
- `/`: full-width showroom hero, where a film of the walk into the showroom plays behind the title (on phones, an upright film panning across the showroom fills the hero), with make, model, budget and availability search; specialties marquee; "What we offer" service panels; a featured stock carousel with in-stock/sold/all tabs; a sell-your-car banner over a view of the showroom; supplied customer reviews; and the contact section ("Start your journey with us today") with a satellite Google map of the showroom, where the About us and Our story links land.
- `/stock`: a hero slab (with a film of the showroom line-up on tablets and desktops) with keyword search and sorting, then available/sold/all pill tabs, make and body pills, transmission and price filters (a drawer on phones), saved cars, the car grid and a banner to find a car or call us. Cards show the year and variant. Hero searches from the home page arrive with their make, model and budget already applied, and `/stock?saved=1` opens the saved view.
- `/stock/:id`: a classifieds-style listing with a breadcrumb, Save and Share; a large photo stage with swipe, arrows, thumbnails and fullscreen viewing (single photos have no carousel controls); key details, dealer comments and a location card; a side column with the price, the illustrative repayment calculator and an "Ask Madi about finance" link, the specifications and a Call Us card (Talk to Madi once a car has sold); a call bar on phones with a Call Us button; and more cars from the collection. Sold cars offer the car finder instead.
- `/stock/manage`: the stock manager, where Madi adds cars from their rego and state, and updates or marks them sold (see below).
- Unknown routes and cars show the same hero slab with a link back to stock.
- The website uses the black and red theme, with charcoal panels, keyboard-accessible themed dropdowns and locally hosted Big Shoulders Display headings. Saved cars persist in the browser.
- Motion (`src/motion.css`): pages crossfade, and a car's photo morphs from its card into the listing's photo stage and back again on Back, which also returns the visitor to the same place in the list (view transitions through React Router's data router, in browsers that support them). Hero titles and section headings rise word by word; the home hero photo slowly zooms and its title lifts away as the page scrolls; the specialties run as a slow marquee; the showroom map wipes into view; the black Clubsport drives into the red "Next up." panel; hovering a card with a mouse fades in the car's second photo; and once the hero has scrolled away the header floats as a compact frosted bar. The home and stock heroes play muted showroom films (`HeroFilm` in `src/main.jsx`). Each film loads after the page, fades in over the hero photo while it plays, pauses when scrolled off screen, and has a pause button that also stills the marquee; the choice is remembered. Visitors who prefer reduced motion get the static page: no films, transitions, marquee or scroll effects. Visitors on data saver also keep the hero photos.

## Stock manager

`/stock/manage` is the real stock system. Madi signs in, enters a car's rego and state (or its VIN), and the details fill themselves in from the rego record through [CarRegistrationAPI](https://www.carregistrationapi.com.au/) (AUD $0.30 a lookup; repeat lookups within 30 days are free). He checks them, adds photos (resized on the phone), the price and kilometres, and puts the car on the website. Each change rebuilds the site through a Vercel deploy hook, so new cars get their own pages, link previews and sitemap entries within about a minute. Rego and VIN details stay private. Cars and photos are stored in a Vercel Blob store; the API is a Vercel function (`api/stock.js`, logic in `server/stock/`).

It's switched on with four Vercel settings: `STOCK_ADMIN_PASSWORD`, a connected public Blob store, `STOCK_DEPLOY_HOOK_URL` and `REGCHECK_USERNAME`. Until then, the page shows a setup checklist and the website keeps the sample listings. Step-by-step setup, how to use it, how it works and the development sample regos are in [`docs/stock-manager.md`](docs/stock-manager.md). In the dev server it works out of the box with the password `mm-dev-password` and sample lookups (try `S123ABC` in SA).

## Stock management concept

Open `/stock-manager` for an interactive presentation of a Telegram stock assistant beside a dealership website preview. Try **Add new vehicle**, **Update listing**, or **Mark vehicle sold**. The add flow accepts a photo album, demonstrates a registration/state lookup, supports manual vehicle details, and asks for kilometres and price before a final publish confirmation. Use **Reset demo** to restore the original sample inventory.

Registration lookup and publishing are simulated. Uploaded photos stay in the browser, and changes affect only the concept preview; the public stock pages are unchanged. The working stock system is the [stock manager](#stock-manager) at `/stock/manage`.

With the development server running, validate the concept with `npm run test:stock-manager`.

## Dealership CRM mockup

Open `/crm` for a one-page customer and sales pipeline mockup. The customer list and pipeline board share editable stages from **New enquiry** through **Test drive**, **Deposit paid** and **Delivered**. Open a customer to see their vehicle interest, trade-in and finance context, add comments, or set their next follow-up. Leads can also be moved by dragging cards between pipeline columns. Search, stage filters, new enquiries and **Reset demo** are interactive.

All customers are samples and edits stay in this page until it is refreshed or reset. Follow-up dates and times use the dealership's Adelaide timezone. No messages are sent or real customer records changed. With the development server running, validate with `npm run test:crm`.

## Content

Sample vehicle data is in `src/data.js`; photo assets are in `public/images`. Every photo comes from MM Prestige Motors, and the hero films from the dealership's walkthrough clips. The home, stock and 404 heroes, the "Next up." panel and every listing use photos from the October 2026 showroom shoot; the sell-your-car banner (the showroom from above, under the wall sign) and the "Performance" panel use two photos from the dealership's phone, also sent in October 2026 (see [photo sources](docs/photo-sources.md)). The About us and Our story links land on the home page's contact section. Madi's portrait from the shoot sits on the Call Us card on each listing and on the home page's "Talk directly with Madi" tile. Available cars show their merchandising tag (for example "The icon" or "Just arrived") on the card photo. Each sample listing shows a car photographed at the showroom, but its year, price, kilometres and specifications are examples, and the pages say so; replace them with verified details before launch. The specialties strip uses lettering rather than manufacturer logos and does not claim current inventory. Business address, phone and review excerpts come from the user's supplied MM Prestige Motors profile.

The enquiry form prepares a message and opens an SMS link to the supplied dealer number. It does not silently submit to a backend or claim delivery. It has three forms: a general or car enquiry (also used for finance questions), a sell or trade-in form that asks for the car's year, make, model, kilometres, rego, condition and plan, and a car finder that asks for the make and model, years, budget and must-haves. Each builds a tidy SMS message from the answers.

Photos are served as resized WebP files with `srcset`. `scripts/photos/export.py` makes the shoot photos in `public/images` from the original files, with one colour grade for the whole site (see [photo sources](docs/photo-sources.md)); the two phone photos have the same grade but aren't remade by it. After adding or replacing photos in `public/images`, run `npm run images` to regenerate `public/images/opt` (480 to 3200 px wide, never upscaled), the 1200 × 630 link-preview crops and `src/image-variants.json`. `scripts/films/build.sh` rebuilds the hero films in `public/video` from the walkthrough clips. It stabilises the walking bounce, upscales with Real-ESRGAN, adds slow motion and eased dissolves, and encodes AV1, HEVC and H.264. It needs ffmpeg with libx264, libx265 and libsvtav1, and Python with OpenCV, SciPy, ONNX and ONNX Runtime; see the script for details. `scripts/films/mobile.sh` makes the phone hero's upright film from the dealership's HDR phone clip: it converts HDR to SDR, steadies the pan, plays it forwards and then backwards as a seamless loop, and saves the graded first frame as the phone hero photo (`public/images/showroom-mobile.jpg`). `npm run share-image` re-renders the branded `public/og-image.png` over the showroom photo, and the app icons. While `sampleStock` in `src/data.js` is `true`, car link previews say "sample listing" and the listings aren't given to search engines as structured data; set it to `false` once the stock and prices are real. Call and Google Maps links use the supplied business details. The contact section's map is Google Maps' keyless embed of the address as a satellite view (`SHOWROOM_MAP` in `src/main.jsx`; it needs no API key). Visitors can drag and zoom it; the address, phone and Get directions links sit beneath it.

The repayment calculator is illustrative, excludes fees/balloons and does not represent a finance offer. Confirm actual finance facilities and required disclosures before using it commercially.

## Design references

The public pages adapt the showroom design developed for the Impulse Automotive concept: charcoal surfaces, condensed uppercase Big Shoulders Display headings, a showroom hero with working search, staggered service panels, compact inventory cards, a sell-your-car banner and a rounded white footer. Its yellow controls are recoloured to MM's red. A deeper red (`#d42536`) sits behind white button text for at least 4.5:1 contrast, and a lighter red (`#f45b67`) is used for small text on charcoal; the `--accent` token remains `#ed3545`. The red tokens (`--accent`, `--accent-strong`, `--accent-text` and their hover variants) are set in `src/direction.css`; other MM-specific styles, including the reviews section, specialties lettering and the admin heading font, are in `src/mm-prestige.css`. The stock and 404 pages follow the home page's layout rules: each opens with a rounded hero slab under the overlaid header (footnote top-left, a light info card, a display title and a glass control bar), and their sections reuse the home page's headings, offer panels, info cards, map, pill tabs and car cards on the same 4% gutter. Vehicle pages use a classifieds-style listing in the same style. A breadcrumb with Save and Share and the full-width title sit above two columns. On the left are a large photo stage with a thumbnail strip, the key details, dealer comments and a location card; on the right, matching cards hold the price and repayment estimate, the specifications and a Call Us contact card. Red is kept for actions. On phones the photos come first, then the title, price, key details, comments, specifications and the call card, and a slim bar keeps the price and a Call Us button at the bottom of the screen. The stock and vehicle page styles are in `src/inner-pages.css`, and the display typeface sizes for every page are in `src/typeface.css`. Listing photos are full-size crops from the shoot (up to 3,200 px wide), so the large stage and the fullscreen view stay sharp. See [design notes](docs/design-research.md) and [photo sources](docs/photo-sources.md). Live boutique-site research was blocked by the environment's network policy; the two alternative palettes are design recommendations, not claims about inspected websites.

## Browser validation

With `npm run dev` running in another terminal, run `npm test`. The suite covers 63 checks: branding and contact details, the black and red theme, sample-content disclosures, the CRM and stock-manager routes, hero search and themed dropdowns, the featured carousel, reviews, the sell banner and Performance photos and card tags, the About us link and the contact section's satellite map (with nothing over it), the specialties marquee and floating header, the hero films (sources for desktops, small tablets and phones, the upright phone film at 720 and 1,080 px over its full-height still, playback, pausing, and the photo fallback for reduced motion and phones), the card-to-listing photo morph and Back scroll position, stock filters and sorting, saved cars and the header saved-cars link, resized WebP photos, link-preview tags and dealer details, the vehicle photo stage, thumbnails and lightbox, breadcrumb, save and share, the listing layout and phone call bar, specifications, finance, the enquiry, sell/trade-in and car-finder forms, the 404 page, keyboard focus, reduced motion, mobile navigation and filters, overflow at 360/390/768px, wide-screen layout, image loading and runtime errors. It uses system Chromium when present; otherwise install Chromium with `npx playwright install chromium`. Override the server URL with `MM_BASE_URL` and the browser executable with `MM_CHROMIUM_PATH` if needed. Screenshots and a results JSON are written to the ignored `.screenshots/` directory. `npm run test:pages` builds the site and checks the generated pages: per-car titles, canonical URLs and preview images, the 404 page, `robots.txt`, `sitemap.xml` and the Vercel routing; a second build from a stock-manager snapshot checks real cars get the same. `npm run test:stock` checks the stock manager: its lookups, records, sessions and storage, then the whole flow in a browser against its own dev server and temporary store (no running server needed). The smoke tests expect the sample listings, so clear `.stock/dev` first if you've published cars in the dev server.

Standalone CRM, stock-management and presentation concepts retain their existing routes, content and styling.
